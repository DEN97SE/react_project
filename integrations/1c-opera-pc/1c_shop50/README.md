## Состав карточки и каталога

В каталог входят непомеченные элементы, которые имеют статус Активный в назначенной текущему магазину матрице или ненулевой суммарный остаток на его складах. Статус Закрытый в назначенных матрицах исключает товар даже с остатком. При конфликте назначенных статусов Закрытый имеет приоритет. Прочие статусы не приравниваются к Активный; возможность продажи Пробный/Сезонный/Утвержденный отдельно не определена. Общая ветка ненулевого остатка их может включить, что само по себе не разрешает продажу.

Нет дополнительного отсева по цене/штрихкоду: их отсутствие передаётся как актуальное состояние полной карточки. Цена не подменяется нулём. Полный набор штрихкодов заменяет предыдущий; promos=[] снимает акцию; нулевой stock.quantity обнуляет остаток. Отрицательное количество не означает доступный положительный запас.

name: непустое предопределённое свойство НаименованиеДляЦенника из ЗначенияСвойствОбъектов, иначе обычное Наименование. Сохраняются страна, состав/КБЖУ при наличии, производитель, категория, цены/акции, штрихкоды и остаток. Денежные и количественные значения — десятичные строки, даты — UTC с учётом пояса сеанса.

Пометка удаления или выход из состава возвращает ID в deleted_nomenclature_ids. Это снятие из каталога магазина, а не физическое удаление в 1С. Полная карточка и снятие должны применяться бэком с учётом версии. Физическое удаление ссылки без заранее сохранённого внешнего ID пока не поддержано.

## Работающий сервис и маршруты

Сервис **ExchOperaPC**, адрес `http://program58:9090/applications/Opera-PC`:

- Opera: `Основной_ExchangeOpera_FromOpera` → общий бэк Opera.
- PC: `Основной_PriceChekerExc_FromShops` → конкретный бэк своего магазина.
- Входящий обработчик Opera вызывает КХ_ОбменШиныОпера.ОбработатьВходящееСообщение.
- Входящий обработчик PC вызывает КХ_ОбменШиныПрайсЧекеры.ОбработатьВходящееСообщение.

Имена внешних узлов и фактические AMQP destinations берутся из опубликованной схемы. Старые варианты длинных имён в исторических папках не являются инструкцией переименовывать уже работающие каналы.

Код отправителя по умолчанию — astor + код СЕ, для тестовой базы сейчас astor123. При необходимости фактический код можно сохранить через УстановитьКодУзлаОтправителя. Для PC предусмотрен явный код адресата: настройка КодПолучателяПрайсЧекеры либо предлагаемый шаблон pricechecker + код СЕ. Для магазина №50 получается **pricechecker123**. Этот участник не создаётся кодом BSL: код/группы/доступ должны быть заведены или сопоставлены в Шине. Адресация по 500 бэкам отдельно проверяется, широковещательная доставка всем PC-бэкам не требуется. Секреты хранятся в настройках сервиса, а не исходниках.

Бэки подключаются напрямую по AMQP 1.0 к 1С:Шине. Внешний RabbitMQ не требуется. HTTP9090 и транспорт AMQP — разные подключения; использовавшийся в тесте порт AMQP6698 и актуальный listener проверяются по настройкам сервера.

## Общая очередь и изоляция прежнего обмена

Используется существующий независимый регистр ОчередьШины. Его ключи включают объект, транспортный ID, канал, получателя и внешнюю систему. Собственное логическое замещение ограничено объектом, получателем, каналом и системой.

| Внешняя система | Содержимое |
| --- | --- |
| Opera | Неизменяемый full/delta для общего бэка, ключ batch_id |
| PriceCheker | Независимый full/delta для PC своего магазина, ключ собственный batch_id |
| OperaChange | Маркер изменения; технический узел КХ_OperaChange |
| OperaState | Счётчик/эпоха/прогресс и отдельный неизменяемый список full |
| StructuralUnits | Отдельные неизменяемые пакеты справочника из ЦО, проект и область в JSON |

Список full имеет идентификатор session_id (UUID36), технический узел КХ_OperaFull и не отправляется. Он удаляется после постановки финальных пакетов. Основную запись КХ_OperaState не удаляют: там revision/source_epoch и прогресс. Технические узлы не являются участниками Шины.

В присланном штатном Интеграция1СШина уже стоят четыре динамических фильтра: отправка, отмена зависших, очистка и обработка квитанций. Они читают СистемыСобственнойОчереди и теперь исключают пять тегов, включая StructuralUnits. Новых изменений в штатный модуль эта правка не требует. Подтверждённые товарные пакеты и справочник очищает отдельный УдалитьПодтвержденныеПакеты; неподтверждённые и OperaState сохраняются. Техническое состояние СЕ использует отдельные ключи КХ_СЕState, КХ_СЕChange и КХ_СЕFull внутри OperaState.

## Регистрация и задание

Существующее задание пользователя **КХ_ОбменШиныОпера**, метод КХ_ОбменШиныОпера.РегламентнаяОбработкаОчередиОпера, каждые 10 секунд. Теперь оно подготавливает общую дельту/до двух порций full и отправляет до 20 пакетов каждого проекта. Вторая копия сборщика для PC не создаётся. Код работает короткими проходами, без ожидания ответа внутри сеанса.

Подписки номенклатуры, штрихкодов, цены, акции, двух регистров свойств и партий сохраняются. Добавляются АссортиментныеМикроматрицы и назначения микроматриц: подробные источники и обработчики в Установке. Источник ПартииНоменклатуры должен быть в одной нашей подписке, а не одновременно в отдельной и общей.

Служебные и пользовательские изменения записываются в одной транзакции; отказ записи откатывает отметку. Два получателя регистрируются атомарно до фиксации снятия отметок/сдвига full. Изменение матриц может затронуть много товаров и требует теста времени записи. Новые подписки ещё не выполнены в базе; метаданные их регистров пока не присланы, известные поля подтверждены диагностикой 07/08.

СервисыИнтеграции.ВыполнитьОбработку запускает общий механизм включённых сервисов. На тестовой копии проверить их использование/адреса; ОстановитьОбработку после каждого своего прохода не добавлять.

## Бэки и оставшиеся проверки

[Контракт бэка](Контракт_бэка.md) описывает два потока, состав, версии и независимые ACK. В общей базе Opera цена/остаток хранятся по store_id + nomenclature_id. Полная сессия одного магазина заменяет только его часть, не данные других магазинов. Локальный PC-бэк принимает только свой store_id.

Пилот: один магазин, два получателя, сборка порции, закрытие/обнуление/матрицы, ACK только одной системы, повтор и перезапуск full, затем второй магазин для проверки адресации. До этого массовое подключение 500 источников не проверено. Обновление справочников стран/единиц/групп, владельцев складов и категории цен СЕ требует отдельной регистрации зависимостей либо новой полной загрузки. Старые lookup-проверки и отчёты в исторических папках сохранены как история; текущий сценарий — эта инструкция.
