# Дополнение 27.10.2026: общий справочник для Backend_PC

Добавлен явный режим pc_directory_node. В нём PC получает полный список магазинов порциями, project=pricechecker, scope_store_id=null. Ключ full: project+scope_store_id+source_id+directory_epoch+session_id. Нумерация полная, как у Opera; у каждого проекта и каждой порции свой batch_id. Приёмник собирает все порции до публикации полного списка и учитывает более новые delta. Выборочная карточка передаётся как delta с той же общей областью, не заменяя остальные магазины. ACK требует scope_store_id=null и остальные поля ACK справочника.

Прежние локальные pc_routes сохранены как альтернативный режим: каждой базе только её СЕ и область store_id. Одновременно общий адрес и локальные маршруты настройка не допускает. Новая доставка ещё не проверена в 1С и на бэках. Ниже описан прежний локальный режим.

# Формат structural_units и ACK

message_type=structural_units, schema_version=1, project=opera|pricechecker. Заголовок ТипСообщения=StructuralUnits. Общая очередь: ВнешняяСистема=StructuralUnits, независимый batch_id для каждого адресата и каждой порции. Тело неизменно при повторе, транспортный ID меняется. Это не товарный пакет products и не переименование уже работающих каналов.

Обязательные поля: source_id, source_node, directory_epoch, directory_revision (целое строкой), batch_id, created_at, kind=full|delta, scope_store_id, structural_units, deleted_structural_unit_ids. В full также session_id, sequence, total_batches, is_final. У Opera scope_store_id=null и полный справочник разбивается на порции; у PC scope_store_id равен своему store_id, full одной СЕ содержит sequence=1, total_batches=1, is_final=true. Одинаковый session_id у PC разных магазинов относится к разным областям, ключ полной сессии включает project+scope_store_id+source_id+directory_epoch.

Карточка: id (тот же store_id товаров), code (код СЕ), store_number (отдельный номер магазина), name, unit_type=store, address, is_working, opening_date, closing_date, coordinates_raw, format, territory, region. Даты календарные YYYY-MM-DD/null, без пересчёта UTC. При is_working=true closing_date=null. Признак Работает=Ложь сам по себе не означает удаление: новая/неработающая СЕ остаётся в справочнике. format/territory/region — объект {id,name} либо null; отсутствующее значение заменяет старое. Поля подключений не входят в DTO.

Удаление по ID означает снятие СЕ из справочника магазинов. Причины: пометка удаления, физическое удаление либо переход в другой вид СЕ. Восстановление даёт обычную карточку более новой версии. Для неизвестного ID удаление также сохраняет версию. Нельзя делать физический каскадный сброс всего товарного каталога по одному событию справочника без отдельной политики. Поздние products не восстанавливают удалённую СЕ.

directory_revision сравнивается численно внутри source_id+directory_epoch. Версия хранится для карточки и её удаления. Дубли batch_id повторно подтверждаются без повторного эффекта. Перед публикацией full нужно собрать все порции, учесть более новые delta, только затем переключить справочник соответствующей области. is_final не означает наличия остальных sequence. Общий full справочника не заменяет товарные таблицы, локальный PC-full затрагивает лишь свою СЕ.

Пример ACK от PC (значения source_id/directory_epoch/batch_id берутся из принятого пакета):

```json
{
  "message_type": "ack",
  "dataset": "structural_units",
  "project": "pricechecker",
  "source_id": "ID_ИСТОЧНИКА_ЦО_ИЗ_ПАКЕТА",
  "directory_epoch": "ЭПОХА_СПРАВОЧНИКА_ИЗ_ПАКЕТА",
  "scope_store_id": "3370588b-0742-11e0-b9c1-001a64c3f566",
  "batch_id": "UUID_ПАКЕТА_PC",
  "status": "processed"
}
```

Для Opera project=opera и scope_store_id=null. После надёжной фиксации пакет подтверждается status=processed; status=error с error сохраняет его для повтора. Поздняя ошибка не снимает успешный ACK. AMQP settlement сам по себе прикладным ACK не является.

ACK возвращается на source_node источника ЦО, через обратный канал соответствующего проекта. Код отправителя интеграционного сообщения должен совпадать с исходным УзелПолучатель: он проверяется по метаданным сообщения, не берётся из произвольного поля JSON. Дополнительно проверяются источник, эпоха, проект входящего канала, область и batch_id. PC не подтверждает Opera и другой магазин. Товарный ACK без dataset по-прежнему имеет прежний формат и проверку store_id; для справочника нельзя подставлять batch_id в штатную транспортную квитанцию.

Входящие запросы полной выгрузки со стороны бэка в этой редакции пока не поддерживаются. Их плановый контракт сохраняется в Контракт_справочника_и_запросов.md; до диспетчера запросов применять только описанные здесь исходящие structural_units и ACK.
