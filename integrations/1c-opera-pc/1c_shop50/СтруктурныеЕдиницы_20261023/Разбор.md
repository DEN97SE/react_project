Описание отсутствовавшего XML ниже относится к первой партии, повторная отправка файлов не нужна.

Подтверждено: Код СЕ — число из 3 знаков; НомерМагазина — отдельное число из 7 знаков. Их нельзя подменять друг другом. Адрес — строка 150; Работает — булево; ДатаОткрытия и ДатаЗакрытия — календарные даты без времени. ГеографическиеКоординаты — строка 50, а не готовые latitude/longitude. СмещениеПоВремени — число 4,2: XML не определяет его единицу и точку отсчёта, поэтому оно не публикуется как UTC-смещение. ВидСтруктурнойЕдиницы имеет тип ПеречислениеСсылка.ВидыСтруктурныхЕдиниц; извлечённая строка кода из Form_4.bin подтверждает точное значение `Перечисления.ВидыСтруктурныхЕдиниц.Магазин`.

Склады имеют владельца СтруктурныеЕдиницы — текущий расчёт остатка по складам своей СЕ соответствует этой связи, новые XML не требуют менять уже проверенный расчёт. СЕ ссылается непосредственно на ТерриториальныеОбразования. ТерриториальныеЕдиницы отдельно ссылаются на них через Город; обратное соединение без конкретной связи с СЕ может размножить карточки, поэтому его нет. Регион карточки берётся из прямого реквизита СЕ.СубъектРФ; другой регион из территории не подставляется неявно.

Подготовлен новый **читающий** модуль КХ_ДанныеСтруктурныхЕдиниц: выборка магазинов по точному виду без фильтра Работает, карточки и явные ID снятия для помеченных/вышедших из вида Магазин ссылок. Состояние включает id, code, store_number, name, address, unit_type, is_working, даты деятельности, coordinates_raw, format, territory, region. Справочные вложенные значения — GUID ссылки и имя, пустые — null. Даты календарные YYYY-MM-DD/null. Полей подключения и произвольной сериализации объекта нет. Физически отсутствующая ссылка не считается автоматически удалённой: нужен ID, сохранённый до удаления.

Инструкция установки **только этого модуля** и сценарий 11: [ПроверкаСборщика.md](ПроверкаСборщика.md). Это проверка формирования данных. Публикация справочника, подписки, ACK и новые входящие запросы бэка этим модулем не включаются. Товарные модули при разборе последних файлов не изменены.

## Подтверждено исходниками

* ObjectModule.bsl: ПриЗаписи и ПередУдалением вызывают штатный контроль изменения в центральном узле. ПередЗаписью отдельно обрабатывает создание СЕ и разрешает загрузку в магазин из обмена, при прочих условиях проверяя роль мастер-данных. Есть действующая регистрация загруженного объекта в сетевом обмене. Наш будущий обработчик должен дополнять эту логику подпиской, а не заменять модуль.
* В модуле используется `ОбщиеПроцедурыИФункцииПовтИсп.ЭтоБазаЦентральногоОфиса()` — найден штатный способ определения роли базы. Для публикации авторитетного справочника проверяется роль ЦО. Один `ОбменДанными.Загрузка` не определяет роль базы; возврат по этому признаку во всех случаях может пропустить важное изменение в самом ЦО.
* Предопределённые элементы: ЦентральныйОфис (код 100) и СобственноеПроизводство (101). Коды не нужны как жёстко заданный фильтр: используются предопределённые ссылки и фактический вид СЕ. Справка перечисляет виды «распределительный центр», «центральный офис», «магазин», однако внутренних имён значений перечисления в этих файлах нет.
* ManagerModule.bsl содержит определение виртуального склада импорта по организации/свойству. Это не готовый фильтр магазинов и не источник адресации к новым бэкам.
* Form.xml содержит 76 привязок к данным. Среди них Адрес, ВидСтруктурнойЕдиницы, Работает, ДатаОткрытия, ДатаЗакрытия, СмещениеПоВремени, ГеографическиеКоординаты, КатегорияЦенРозницы, Филиал. Наличие привязки помогает найти реквизит, но не доказывает его тип/обязательность/актуальную бизнес-семантику.
* В форме также есть реквизиты подключений и учётных данных. Для внешней карточки СЕ выбирается явный перечень нужных полей; выгрузка всех реквизитов объекта не подходит.

## Предлагаемый состав карточки

| Поле бэка | Источник 1С | Статус |
| --- | --- | --- |
| id | СтроковыйИдентификатор | Уже используется как store_id в работающем обмене товаров |
| code, name | Код, Наименование | Стандартные поля; код передавать строкой |
| address | Адрес | Найден в форме; тип ещё проверить |
| unit_type | ВидСтруктурнойЕдиницы | Найден в форме; нужны точные имена значений |
| is_working | Работает | Найден в форме; тип и смысл проверить |
| opening_date, closing_date | ДатаОткрытия, ДатаЗакрытия | Найдены в форме; это даты деятельности, часовой пояс/формат согласовать после типа |
| time_offset | СмещениеПоВремени | Найден в форме; единица измерения и смысл пока неизвестны, не объявлять его UTC-смещением |
| coordinates | ГеографическиеКоординаты | Найдено в форме; структуру не разбирать по предположению |

Пометка удаления передаётся явным событием снятия по сохранённому ID. `Работает=Ложь`, будущая дата открытия, дата закрытия и ПометкаУдаления — разные состояния. Для справочника магазинов не следует автоматически отбирать только Работающие: тогда бэк не узнает о новых, ещё не открытых магазинах, а закрытый может молча исчезнуть. После выбора точного значения вида базовый список включает магазины всех состояний с явными признаками; правила доступности на бэке определяются отдельно.

Физическое удаление: новая подписка ПередУдалением должна сохранить внешний ID/событие в той же транзакции, в которой удаляется объект. Если штатный контроль отказал или транзакция откатилась, внешнее событие также не должно сохраниться. При записи — подписка ПриЗаписи после проверки Отказ; события реплик в магазинах не публикуют авторитетный справочник. Начальная полная выгрузка из ЦО всё равно обязательна, подписки не создадут сведения обо всех старых СЕ задним числом.

## Что подготовлено сейчас

`АвтоматическаяРегистрация/10_ПроверитьСтруктурныеЕдиницыБезОтправки.txt` — самостоятельная диагностика для консоли «На сервере», без установки модулей, изменения очереди и отправки. Она показывает роль базы, имена/типы реквизитов, внутренние имена значений перечисления вида, количество элементов по видам/пометке и только разрешённые значения текущей СЕ. Значения полей подключений/паролей не выбираются. Её можно выполнить в тестовом магазине №50; результат не заменяет проверку роли и запуска в настоящем ЦО.

Для точной реализации нужен один корневой файл выгрузки конфигурации: `Catalogs/СтруктурныеЕдиницы.xml`. Он лежит **рядом с папкой** `Catalogs/СтруктурныеЕдиницы`, внутри которой лежат присланные Ext/ObjectModule.bsl, Ext/ManagerModule.bsl, формы и справка. Аналогичные XML форм не заменяют этот файл. Результат диагностики 10 позволит продолжить проверку полей даже без него; дополнительные формы не нужны.

Сборщик/регистратор справочника ЦО, его отдельные версии/ACK и новые запросы бэка пока не реализованы. Установка файлов из этой папки не требуется. Работающие товарные модули и штатный сетевой обмен не изменялись при данном разборе.
