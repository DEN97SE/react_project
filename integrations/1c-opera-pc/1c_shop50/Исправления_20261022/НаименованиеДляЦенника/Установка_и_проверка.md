# Наименование для ценника с резервным обычным наименованием

Источник подтверждён пользователем в базе: предопределённый элемент ПВХ СвойстваОбъектов.НаименованиеДляЦенника; значение товара хранится в РС ЗначенияСвойствОбъектов (одна запись). У тестовых бананов оба наименования пока совпадают: «Бананы 1кг». GUID для реализации не используется.

## Изменение

Общий сборщик КХ_ДанныеОпера получает значение свойства левым соединением, передаёт его через ВТ_Номенклатура в сборку карточки. Если после обрезки пробелов оно непустое — это name. При NULL (нет записи), Неопределено, пустой строке или строке из пробелов берётся прежнее Номенклатура.Наименование. Если оба имени пусты, сохраняется прежнее поведение — карточка не формируется.

Ссылка на свойство задаётся через ЗНАЧЕНИЕ(ПланВидовХарактеристик.СвойстваОбъектов.НаименованиеДляЦенника). Отсутствие значения свойства у товара не равно отсутствию самого предопределённого элемента в другой несовместимой конфигурации; подтверждённое имя относится к конфигурации пользователя.

Правка общая для full/delta Оперы и ответа ПрайсЧекеров. Контракт остаётся прежним, меняется только источник поля name. Изменены две функции: ПолучитьДанныеДляВыгрузки и СформироватьТовар. Четыре изменённых фрагмента отмечены блоками semidockij - 22.10.2026; остальной текст исходника сохранён.

## Установка

В тестовой базе заменить только общий модуль КХ_ДанныеОпера текстом ДляКопирования/КХ_ДанныеОпера.txt. Если в нём есть дополнительные локальные изменения, заменить только две функции из файлов этой папки или применить КХ_ДанныеОпера.diff. Не смешивать оба варианта установки.

Проверить синтаксис, выполнить F7, перезапустить сеанс. Другие общие модули и сервис интеграции ради этой правки не заменяются.

Для автоматической регистрации именно изменения этого свойства нужна подписка РегистрСведенийНаборЗаписей.ЗначенияСвойствОбъектов / ПередЗаписью → КХ_ОбменШиныОпера.НаборЗаписейПередЗаписью. Она описана в АвтоматическаяРегистрация/Покрытие_ТЗ_и_свойства.md; факт её установки в базе отдельно не подтверждён.

## Проверка на одном товаре

Обычное наименование тестовых бананов оставить «Бананы 1кг». В форме товара менять именно значение свойства «Наименование для ценника», затем сохранять.

| Состояние значения свойства | Ожидаемое name |
|---|---|
| Бананы — проверка ценника | Бананы — проверка ценника |
| Пустая строка | Бананы 1кг |
| Пробелы | Бананы 1кг |
| Записи значения свойства у товара нет | Бананы 1кг |

Для проверок выполнить АвтоматическаяРегистрация/05_ПроверитьИмяКарточки.txt через кнопку «На сервере». В начале сценария указать ожидаемое имя для текущего случая. Он читает оба пути (Опера и ПрайсЧекеры), не вызывает регистрацию/отправку и не изменяет свойства товара. Для отсутствующей записи можно взять другой тестовый товар без значения свойства и поменять штрихкод/ожидаемое имя в сценарии; ручное удаление регистра не требуется.

Отдельно проверить, что реальное изменение/очистка свойства создало новую OperaChange (при выключенном сборщике) либо новый пакет с правильным name (при работающем задании). Если сравниваем одинаковые обычное и ценниковое имена, такой тест не доказывает приоритет свойства — первый случай специально задаёт различающиеся строки.

После проверки восстановить исходное значение тестового свойства. Результат выполнения в базе пользователя пока не получен; статическая проверка фиксируется в СТАТУС_ПРОВЕРКИ.md и не заменяет эти сценарии.
