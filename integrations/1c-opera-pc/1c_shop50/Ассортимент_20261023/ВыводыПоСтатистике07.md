# Результат диагностики 07 и следующий отбор

23.10.2026 пользователь прислал успешное выполнение 07 в магазине «Командор №50», момент 11:38:19 местного времени. Успешный запрос подтверждает наличие использованных регистров и полей в этой базе. Метаданные регистров всё ещё полезны для будущих подписок и учёта периодичности, но не нужны повторно для доказательства существования источников. Структурированные числа сохранены в `РезультатДиагностики07.json`.

| Признак | Товаров |
| --- | ---: |
| Все элементы без групп и пометки удаления | 357 621 |
| Есть штрихкод | 356 405 |
| Есть текущая розничная цена | 125 253 |
| В назначенной матрице с непустым статусом | 153 652 |
| Статус Активный в назначенных матрицах | 18 123 |
| Статус Пассивный | 135 307 |
| Статус Закрытый | 222 |
| Положительный остаток | 11 576 |
| Нулевой остаток | 345 840 |
| Отрицательный остаток | 205 |
| Вне матриц с непустым статусом, но с ненулевым остатком | 526 |

Первую подпись старого сценария «Активных товаров, без групп и помеченных» следует читать как «непомеченных элементов справочника». Это не статус Активный. Подпись в 07 уточнена; расчёт чисел не менялся. Число 18 123 относится именно к статусу в назначенных матрицах.

## Практические выводы

1. Обязательный штрихкод почти не сокращает объём: он есть у 356 405 из 357 621 товаров. При этом в каталоге используются GUID, а необходимость barcode для поиска ПрайсЧекера не является правилом принадлежности товара магазину.
2. Существование цены не ограничивает каталог текущим активным ассортиментом: оно оставляет 125 253 позиций. Сам факт последней цены не доказывает, что товар сейчас продаётся.
3. Любой непустой статус в матрице — слишком широкий отбор: в него попали 135 307 пассивных и 222 закрытых товара. Только Активный даёт 18 123.
4. Один положительный остаток оставит 11 576 товаров; условие штрихкод+цена+положительный остаток — 11 562. Такой отбор исключает часть активного ассортимента и не обеспечивает передачу нулевых остатков.
5. По разности «запись цены ИЛИ ненулевой остаток» и «запись цены» видно 17 товаров с ненулевым остатком без записи текущей розничной цены. Их нельзя выдавать за товары с ценой 0. Доступность и обработка ошибки цены требуют отдельного решения.

Пользователь уточнил: пассивные товары с остатком продолжают продавать; закрытые не продают. Закрытые должны исключаться независимо от остатка. Основа каталога — Активный в назначенной магазину матрице; пассивные с остатком остаются как исключение.

В диагностике 08 оценивается правило: не группа, не помечен на удаление, **НЕ Закрытый И (Активный в назначенной магазину матрице ИЛИ ненулевой остаток)**. Оно включает также не имеющие активной матрицы товары с остатком; такие исключения выводятся отдельно и не означают утверждённого разрешения продажи любого иного статуса. Закрытый определяется в назначенных матрицах текущего магазина. При возможном конфликте статусов диагностический кандидат отдаёт приоритет исключению Закрытый. Отрицательные остатки учитываются в численности и показываются отдельно: пользователь не утверждал их как доступный к продаже запас. Рабочая логика пока не менялась.

Точное количество для кандидата нельзя вывести из 07: нет пересечения активных/закрытых товаров и остатков. Верхняя граница — 29 904 позиций (18 123 + 11 576 + 205), окончательное исключение Закрытый её не увеличит. Число 18 123 нельзя просто сложить с количеством остатков: множества пересекаются. Финальное количество измеряется сценарием 08.

## Ближайший независимый шаг

Подготовлен сценарий `08_ОценитьАктивныйАссортиментБезОтправки.txt`: тот же набор проверенных источников, принадлежность активному ассортименту по предопределённому статусу Активный и отдельное множество Закрытый для исключения. Он показывает точный размер кандидата, количество исключённых закрытых с остатком, количество дополнительно включённых по остатку, число кандидатов без штрихкода/цены и с отрицательным остатком. Общая таблица статусов выводится для контроля.

Сценарий запускается один раз «На сервере», не меняет рабочий отбор и не регистрирует/отправляет пакеты. В нём не происходит реализации бизнес-правила. Статусы Пробный/Сезонный/Утвержденный не приравниваются к Активный: в присланном срезе их нет. При их появлении диагностическая ветка ненулевого остатка их может включить, но правило их продажи ещё не утверждено.

## Требования к будущей правке

- Единый отбор для full и delta Opera.
- На выходе ранее отправленного товара из отбора — явное удаление из каталога магазина либо согласованное состояние. Нельзя просто перестать отправлять его.
- Для активного товара передавать и нулевой остаток; для остальных — переход в ноль согласовать с правилом исключения из каталога.
- Регистрация изменения статуса/назначения матрицы и массового пересчёта затронутых товаров. Текущие подписки на цены и свойства эту зависимость сами не покрывают.
- Сохранить общий сборщик карточек ПрайсЧекеров; ограничение каталога Opera не должно случайно менять ответ на запрос по штрихкоду.
- Оптимизировать full-состояние: текущий массив GUID хранится вместе с revision в OperaState. При большой полной сессии он переписывается при регистрации каждого изменения и остаётся после постановки full-пакетов. Сокращение каталога уменьшит проблему, но не исправит её архитектурно.

Рабочие общие модули и настройки базы в связи с этим результатом не менялись.
