# Обратный транслятор Opera — редакция 2

Первый вариант с ДанныеАдресаОтветаOpera фактически упал на товарном ACK: десериализатор потребовал отсутствующие source_id и dataset. Бэк прислал допустимый товарный ACK с message_type, store_id, batch_id и status. Причина в подготовленном нами трансляторе; добавлять поля СЕ в товарный ACK не требуется.

31_Opera_ОбратныйТранслятор.xbsl обновлён: JSON читается в Соответствие<Строка, Объект?>. Отсутствующие ключи проверяются через СодержитКлюч до Получить. Старый тип ДанныеАдресаОтветаOpera больше не используется; добавлять новую структуру не нужно.

В модуле процесса Opera заменить только метод АдресОтветаPCПреобразование целиком из файла. Сохраняется привязка обратной ветки FromBackend → транслятор → ToBackend. На время публикации остановить процесс Opera, после успешной сборки и публикации запустить.

Один непустой явный получатель, отличный от BackendOpera, сохраняется. Если адреса нет или указан BackendOpera, для товаров используется store_id; для dataset=structural_units или message_type=structural_units_request — source_id издателя. Исходный JSON возвращается целиком через новый поток. Нет/неверный/нулевой UUID, несколько получателей или посторонний отправитель приводят к исключению.

На снимке пользователя FromBackend содержит 1787 сообщений, ToBackend обоих магазинов показывает 0 доставленных; число ошибок 3996 не трактуется как число уникальных потерянных сообщений. Полную выгрузку и очистку очереди для исправления парсинга не запрашивать.

Грамматика редакции 2 проверена сторонним парсером с явным словарём: 0 ошибок. Native-компиляция и выполнение редакции 2 в Шине 8.1.3 ещё не проверены. После публикации проверить новый ACK: сообщение выходит в ToBackend нужного магазина и принимается обработчиком 1С. Автоматический повтор старых сообщений зависит от настройки процесса; немедленная обработка всей очереди не обещается.
