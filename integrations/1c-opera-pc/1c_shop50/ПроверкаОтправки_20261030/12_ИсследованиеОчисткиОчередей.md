# Очистка очередей — что подтверждено и что пока неизвестно

Пользователь просит найти очистку именно серверной очереди 1С:Шины, без удаления канала. Не заменять этот запрос изменением обработчика базы или очисткой исходящего регистра.

## Подтверждено по сохранённой справке установленной Шины

- `ДокументацияШины_20261027/10.txt`, исходный URL `http://program58:9090/docs/help/topics/delivered-messages/`: удаление сохранённых доставленных сообщений, в том числе диапазона для одного узла/участника. Это история доставок, а не команда purge активной очереди.
- `11.txt`, `http://program58:9090/docs/help/topics/undelivered-messages/`: удаление недоставленного сообщения из соответствующего хранилища.
- `27.txt`: пересоздание узлов/сохраняющих маршрутов меняет их идентификаторы и влияет на накопленные сообщения; это не основание предлагать удаление канала как способ обычной очистки.
- В доступных страницах не найден документированный API/команда очистки активного канала `PC / K0050 / ToBackend`. Это отсутствие подтверждения, не доказательство отсутствия функции во всех версиях продукта.

## Независимо найдены API локальной очереди платформы 1С

Публичный проект `https://github.com/kodmis/messages-1c-shina-viewer` описан как просмотр локальных сообщений 1С:Шины. Проверены исходники:

- `СообщенияШины/src/ExternalDataProcessors/СообщенияШины/ObjectModule.bsl`: `СервисыИнтеграции[Сервис][Канал].ВыбратьСообщения(, РазмерВыборки)`; элементы имеют Идентификатор, КодОтправителя, КодПолучателя и тело.
- `СообщенияШины/src/ExternalDataProcessors/СообщенияШины/Forms/Форма/Module.bsl`, строки 369–374: `СервисыИнтеграции[Сервис][Канал].УдалитьСообщения(МассивИдентификаторов)`.

Это рабочий пример для локальной очереди платформы, а не подтверждение серверного purge в панели 1С:Шины. API здесь в платформе не исполнялся. Не путать транспортный Идентификатор элемента с JSON batch_id/ИдентификаторОбъекта товарного регистра.

## Доступ к источникам и оставшиеся данные

- Рабочая Шина `program58` недоступна из текущей среды, VPN не настроен, учётных данных/доступа к панели нет.
- Текущая HTTP-политика среды разрешает GitHub/пакетные репозитории, но не поисковые системы/публичные сайты 1С. Попытка Google завершилась запретом CONNECT 403; повтор с require_escalated также не дал доступа. Настройки сети не изменялись.
- Через разрешённый GitHub выполнен поиск публичных репозиториев/README/issues по 1С:Шине, очистке, очередям, purge и API. Просмотрены клиенты Node.js, примеры, Docker-скрипты; подтверждённой команды серверного purge не найдено. Репозиторий с названием ESB оказался пустым. Никакие чужие скрипты не исполнялись: только чтение исходников.
- У пользователя асинхронно запрошены версия именно 1С:Шины и текст страницы справки установленной версии: `http://program58:9090/docs/help/topics/status-of-1c-channels/`. Эта страница есть в ссылках локального index.json, но её содержимое не сохранено. По получению текста/версии продолжить поиск конкретного штатного действия, не выдумывать меню или HTTP DELETE.
- Временная вставка 11 для снятия чужих ACK в обработчике не передана пользователю и не применена. По последнему требованию пользователя изменение обработчика отложено.
- Пользователь сообщил версию 1С:Шины **8.1.3**. Вопрос о версии закрыт; текст страницы справки пока не получен.
