# Очистка всех сообщений и новая выгрузка только карточек

По последнему уточнению пользователя: «Давай только карточки, но очередь чистим полностью». Это заменяет промежуточный вариант «Все полностью» в части новой публикации СЕ. Очищаются сообщения всех направлений нашего обмена в1С; заново отправляются только products вOpera/PC. В полную товарную карточку входят цена и остаток. СЕ заново не отправляются.

Единственный консольный алгоритм —28_ПолнаяОчисткаОчередейИНовыйКаталог_50_410.bsl. Его выполняют целиком сначала в тестовой50, затем в тестовой410. Проверяются UUID и точное имя тестовойИБ; производственные базы с теми же UUID не допускаются. Код не устанавливается в общий модуль.

Первое выполнение отключает только три вида наших заданий и активность двух наших сервисов. Если найдены ещё активные циклы этих регламентных заданий, запрашивает их отмену и возвращает ожидание без удаления сообщений. Повторить тот же код после завершения остановки.

После остановки удаляются локальные сообщения четырёх нативных каналов, затем в одной транзакции — Opera/PriceCheker/StructuralUnits/OperaChange и технические снимки/запросы OperaState. Сохраняются два корня настроек. У товаров сбрасываются прежняя подготовка full и очередь запросов, штатным API запрашивается новый полный каталог с повышенной revision. У СЕ выключаются публикация и запрос/подготовка full, сохраняются источник, маршруты и эпоха. Ключи и параметры подключения не перезаписываются.

В корне товаров сохраняется отметка TEST_PRODUCTS_20261102_01. Повтор с той же отметкой уже не удаляет новые сообщения: включает сервисы/товарное задание при необходимости и показывает новую сессию/очереди. Служебный КодОчистки при повторе контроля сохраняют прежним. Источник и эпохи остаются прежними, новые batch/session создаются штатным полным циклом.

Возобновляется только общее товарное задание, ежедневно10секунд. СЕ и отдельный старыйPCjob остаются выключенными. История/очередь показываются после включения; повторить через30–60секунд. Ошибки подготовки смотрят вКХ.Шина.

Очищается только собственный обмен в1С. Серверные очереди Шины и данные на бэках не удаляются. Служебные записи настроек остаются в регистре, а новое товарное задание затем создаёт новые пакеты, поэтому общий физический регистр не обязан оставаться пустым.

Синтаксис и используемые API проверены по исходникам. Полный сценарий28 ещё не выполнен в1С; предыдущий входящийPCpurge и отдельные операции настройки уже были исполнены пользователем. Пауза/очистка/новые сессии по этому алгоритму требуют фактического вывода пользователя.
