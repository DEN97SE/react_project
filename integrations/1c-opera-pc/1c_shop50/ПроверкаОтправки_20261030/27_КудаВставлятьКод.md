# Установка отбора СЕ и проверка

В этом шаге два разных места работы. Сборщик устанавливается в конфигурации; проверка выполняется в консоли. Отправка СЕ остаётся только из тестового источника50 в Opera.

1. В консоли кода тестовой базы50 выполнить целиком [27_СЕ_ПаузаИПроверкаОтбора_БезОтправки.bsl](27_СЕ_ПаузаИПроверкаОтбора_БезОтправки.bsl). Он приостанавливает будущие запуски только задания СЕ. Если показан ещё активный цикл, дождаться его завершения перед обновлением конфигурации.
2. В Конфигураторе этой же базы открыть **Общие → Общие модули → КХ_ДанныеСтруктурныхЕдиниц → Модуль**. Полный актуальный текст находится в [КХ_ДанныеСтруктурныхЕдиниц.bsl](../ОбщиеМодули/КХ_ДанныеСтруктурныхЕдиниц.bsl). Он содержит четыре функции: ПолучитьСостояниеМагазинов, КарточкаМагазина, СправочноеЗначение, КалендарнаяДатаВJSON. Это код общего модуля, не алгоритм консоли. Существующие свойства общего модуля сохраняются.
3. Проверить конфигурацию, обновить конфигурацию БД (F7) и обновить сеанс1С. Снова выполнить в консоли **тот же алгоритм27**. Ожидаются работающие магазины без пометки и удалений0 в полном списке. Статусы/состав старых трёх пакетов показываются отдельно и не меняются.

Ошибка «КарточкаМагазина не определена» на скриншоте возникла в консоли при вставке отдельной функции ПолучитьСостояниеМагазинов: частная КарточкаМагазина находится в общем модуле, а не в этом алгоритме. Для работы по расписанию фильтр также должен быть установлен именно в общем модуле.

Выбранная пользователем политика: полный список — только работающие без пометки, первоначальных удалений нет. Ранее переданный магазин после закрытия/пометки отправляется только ID удаления в Opera. Результат установки, пауза задания и runtime27 пока не показаны. Возврат ACK трёх старых пакетов остаётся отдельной незавершённой проверкой;26 не повторять до разбора пакетов, поскольку он включает задание.
