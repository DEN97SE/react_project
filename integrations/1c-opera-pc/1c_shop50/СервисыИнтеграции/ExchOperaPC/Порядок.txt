ПОДКЛЮЧЕНИЕ ПОЛУЧЕНИЯ ACK — МОДУЛЬ СЕРВИСА ExchOperaPC

На скриншоте пользователя в модуле сервиса две процедуры получения, обе пустые. Обратные сообщения есть в канале ToBackend; прикладной обработчик из общего модуля сам собой не вызывается. Нужна передача Сообщение/Отказ из сервисного события в общий модуль. Общие модули сейчас не заменяются.

1. В конфигураторе: Общие -> Сервисы интеграции -> ExchOperaPC -> модуль сервиса. Вставить полный текст ExchOperaPC_ServiceModule.txt вместо двух пустых процедур на скриншоте. Если в этом модуле помимо них есть другой код, сохранить его и заполнить только эти две процедуры.
2. В свойствах каналов проверить направление Получение и привязки события ОбработкаПолученияСообщения к соответствующим локальным процедурам:
   Основной_ExchangeOpera_ToBackend -> Основной_ExchangeOpera_ToBackendОбработкаПолученияСообщения
   Основной_PriceChekerExc_ToBackend -> Основной_PriceChekerExc_ToBackendОбработкаПолученияСообщения
   Выбирать локальные процедуры модуля сервиса; внутри них уже вызываются экспортные методы общих модулей. Если процедуры созданы кнопкой события и имена уже назначены, достаточно сохранить эти привязки.
3. Проверка конфигурации, F7, новый сеанс предприятия. Использовать ту же тестовую базу №50, для которой настроен PC-маршрут. Обновление исходников только в конфигурации без обновления базы не меняет обработчик работающего сервиса.
4. В консоли через «На сервере» выполнить:
   СервисыИнтеграции.ВыполнитьОбработку();
   Отправлять новый пакет или повторять 18/23 сейчас не нужно: ожидаем существующий ACK из обратного канала. Если стоит точка останова, после просмотра продолжить выполнение F5, чтобы обработчик завершился и транзакция зафиксировалась. Пока выполнение остановлено в обработчике, отчёт другого сеанса может ещё не видеть подтверждение.
5. Обновить каналы Шины и выполнить 19: ожидается Доставка подтверждена у PC batch_id 9d4a84df-91c5-43ff-92a2-f1f5557a3408. Затем 22 проверит удаление подтверждённой строки. Общие задания пока выключены, чтобы сначала увидеть переход статуса.

Если Шина уже выдала сообщения в прежний пустой обработчик, а статус в регистре остался Отправлено, бэк повторно отправляет ТОТ ЖЕ ACK с прежним batch_id после установки этой связи. Новый товарный batch_id для этого не нужен. Повторный ACK для уже подтверждённого/очищенного пакета допустим: обработчик не должен создавать новую исходящую запись.

При ошибке тела/ACK общие модули ставят Отказ=Истина и записывают ошибку; эти локальные процедуры не должны её скрывать или принудительно сбрасывать Отказ. Для просмотра JSON в отладчике удобно остановиться внутри общего модуля PC ПОСЛЕ чтения тела и смотреть переменную Запрос; не читать поток сообщения отдельно перед прикладным обработчиком, чтобы не сдвинуть позицию чтения.

Это подготовленная связка на основании имён событий на скриншоте. На платформе пользователя она ещё не проверена. Для текущего теста ожидается только разбор ACK и смена статуса собственного пакета; подтверждение получения в Шине само по себе не доказывает прикладной разбор.
