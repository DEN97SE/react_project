ACK ТОВАРНОГО ПАКЕТА PC — ДЛЯ РАЗРАБОТЧИКА БЭКА

После надёжного сохранения/применения пакета бэк должен вернуть сообщение:
{
  "message_type": "ack",
  "store_id": "3370588b-0742-11e0-b9c1-001a64c3f566",
  "batch_id": "UUID_ИЗ_ПОЛУЧЕННОГО_PC_ПАКЕТА",
  "status": "processed"
}
Точный JSON с реальным batch_id выводится сценарием 19. Это batch_id из JSON, а не transport_id сообщения. При повторе уже сохранённого batch_id бэк возвращает тот же успешный ACK без повторного изменения данных. Ошибка обработки: status="error", дополнительно строковое поле error с описанием; успешный ответ не возвращать до сохранения данных.

Прямой тест 16 не создавал собственную строку ОчередьШины. Для проверки статуса нужен НОВЫЙ пакет из сценария 18 или последующего автоматического изменения. ACK старого теста 16 не подтвердит новый batch_id.

АДРЕСАЦИЯ
Тестовый отправитель ACK: Backend_PC.
Получатель ACK: Magazyni_PC, взятый из source_node полученного нового товарного пакета. Поле source_node добавлено в PC-пакеты этой редакцией. Дополнительное поле нужно принять в DTO/JSON-модели бэка, если она запрещает неизвестные поля. Не подставлять автоматически прежний общий отправитель Opera astor123/MagazyniOpera.
В опубликованной схеме PC ответ идёт через FromBackend -> ToBackend к магазинной инфосистеме. Проверить фактический канал отправки/назначение в используемом клиенте Шины. Транспортный settlement не является этим JSON-ответом.

ПРИЁМ В 1С
В сервисе ExchOperaPC входящий канал Основной_PriceChekerExc_ToBackend должен иметь направление «Получение» и обработчик:
  КХ_ОбменШиныПрайсЧекеры.ОбработатьВходящееСообщение
Названия и привязки исходящего канала FromShops для этого не менять. Если обработчик уже назначен — оставить. После изменения метаданных проверить конфигурацию/F7/новый сеанс.
Этот обработчик передаёт товарный ACK в систему очереди PriceCheker; он не подтверждает Opera. dataset=structural_units здесь НЕ добавлять: это другой контракт ACK справочника.

КРИТЕРИЙ
В отчёте 19/регистре ОчередьШины строка ВнешняяСистема=PriceCheker с присланным batch_id имеет статус «Доставка подтверждена». Статус Opera-пакета с другим batch_id не меняется от этого ACK. Поздний error не должен снимать уже успешное подтверждение. Обратный ответ и этот переход в новой редакции ещё не проверены на платформе.
