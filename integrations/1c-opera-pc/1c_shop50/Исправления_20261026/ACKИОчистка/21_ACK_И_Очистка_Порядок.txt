КАК БЭК ДОЛЖЕН ОТВЕТИТЬ
После надёжной фиксации ВСЕГО принятого пакета товаров бэк отправляет через Шину обратное сообщение JSON (один ACK на пакет, не на товар):
{
  "message_type": "ack",
  "store_id": "3370588b-0742-11e0-b9c1-001a64c3f566",
  "batch_id": "batch_id_ИЗ_ПРИНЯТОГО_PC_ПАКЕТА",
  "status": "processed"
}
Взять batch_id именно из тела принятого пакета; это не транспортный идентификатор. store_id также взять из пакета. После повтора уже сохранённого batch_id повторить успешный ACK без повторной бизнес-операции. При ошибке status=error и строковое поле error с причиной; такой пакет 1С сохранит для повтора. Если пакет применён частично, успешный processed не возвращать до надёжной фиксации всего пакета.

Отправитель сообщения ACK: Backend_PC.
Получатель: значение source_node принятого PC-пакета, в текущем тесте Magazyni_PC.
Опубликованный процесс PC: FromBackend -> ToBackend к магазинной инфосистеме.
В 1С сервис ExchOperaPC, входящий канал Основной_PriceChekerExc_ToBackend, направление Получение, обработчик КХ_ОбменШиныПрайсЧекеры.ОбработатьВходящееСообщение. Назначить его в свойствах входящего канала, если ещё не назначен; проверить конфигурацию/F7/новый сеанс. Транспортное подтверждение чтения сообщения бэком и JSON ACK — разные шаги.

ЧТО ПРОИСХОДИТ В 1С
Настоящий ACK находит собственную запись ВнешняяСистема=PriceCheker по batch_id и store_id и ставит Доставка подтверждена с датой подтверждения. Редакция очистки удаляет такие записи следующим циклом общего задания (каждые 10 секунд), до 1000 за цикл, при ДнейХраненияПодтвержденных=0. Настройки и revision/эпоха в OperaState, отметки OperaChange и неподтверждённые исходящие пакеты не удаляются. Очиститель ограничен собственными исходящими системами Opera/PriceCheker/StructuralUnits, штатный чужой обмен не затрагивает.
Поэтому после автоматической очистки строки может уже не быть в отчёте 19. Для первого теста задание оставить выключенным: сначала увидеть Доставка подтверждена в 19, затем вручную выполнить 22_ОчиститьТолькоПодтвержденныеПакеты.txt и убедиться, что подтверждённая строка удалена. Само отсутствие строки без ранее проверенного ACK не доказывает успех.
При выключенном задании автоматической очистки нет. Публичный метод очистки без аргумента сохраняет прежний срок 30 дней; задание явно передаёт параметр 0. Срок можно увеличить в ПараметрыОбмена, если требуется сохранять подтверждённые тела для диагностики. При сроке 0 дней дата подтверждения не задерживает удаление, в том числе в текущую секунду. Отправлено и Ошибка остаются до настоящего processed; в том числе четыре старых пакета Opera из скриншота не удаляются этим обновлением без ACK Opera.
