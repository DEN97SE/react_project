Программная настройка сервисов интеграции. 28.10.2026.

Основание
Пользователь подтвердил в платформе 8.3.27 методы менеджера сервиса ПолучитьНастройки, УстановитьНастройки, ПолучитьАктивность, УстановитьАктивность.
Результат ПолучитьНастройки имеет тип НастройкиСервисаИнтеграции и четыре свойства:
- АдресВнешнегоСервисаИнтеграции;
- ИмяПользователя;
- ИмяПользователяВнешнегоСервисаИнтеграции;
- ПарольПользователяВнешнегоСервисаИнтеграции.
Свойства адреса, внешнего имени и пароля используются для заполнения параметров подключения: имя внешнего пользователя - идентификатор ключа, пароль - секрет клиента, как в действующей форме подключения. Назначение и требуемое значение отдельного поля ИмяПользователя не меняем: сохраняем текущее. Для полностью пустой новой базы его первоначальное заполнение при необходимости выясняется отдельно по справке и проверяется в фоне.

Что подготовлено
1. Новый общий модуль КХ_НастройкаПодключенийШины.
2. Проверка текущих настроек без вывода значений ключей и секретов.
3. План первоначальной настройки двух сервисов в пилотной базе №50. По умолчанию он только проверяет заполненный план; запись включается локальным параметром ПрименятьНастройки.

Установка
Создать общий модуль КХ_НастройкаПодключенийШины. Свойства: Сервер=Да, ВнешнееСоединение=Да, Глобальный=Нет, Привилегированный=Нет, повторное использование возвращаемых значений=Не использовать. Клиентские контексты и вызов с клиента для этого серверного пилота не требуются.
Вставить полный текст module_connection_setup.txt, выполнить проверку синтаксиса и обновить конфигурацию базы F7.
Установленные семь общих модулей обмена и два модуля сервисов не заменяются этим исправлением.
Требуется право Администрирование данных и корректная область разделения. Обход прав или подстановка пользователя не предусмотрены.

Пилот
Сначала выполнить 01_read_connection_status.txt через «На сервере»; в нём только признаки заполнения и активности. Достаточно прислать этот служебный вывод, секреты не нужны.
Приостановить только наши задания и дождаться завершения текущих запусков до изменения настроек. Действующий сервис может обрабатывать платформенные сообщения независимо: изменение параметров уведомляет механизм о перезапуске. Сам настройщик отправителей не вызывает.
В 02_apply_connection_plan.txt локально заполнить ключи участников, от имени которых сейчас действительно работают сервисы. Не выдавать новые ключи специально ради теста и не менять участника одновременно с проверкой записи настроек.
Адрес пустой в плане означает сохранить действующий адрес. Если адрес не заполнен и в базе, проверка остановится до записи. Для новой базы центр должен передать фактический адрес подключения, используемый штатной формой; ссылку на документацию или отладочную сессию туда не подставлять.
Первый запуск: ПрименятьНастройки=Ложь. Запись не выполняется, в сообщения не выводятся секреты.
После проверки плана применение можно выполнить с ПрименятьНастройки=Истина. Запись происходит последовательно; два сервиса не объявляются одной атомарной операцией. Итоги показывают, какие вызовы уже состоялись и на каком этапе произошёл сбой. При ошибке следующие сервисы не обрабатываются.
План не задаёт активность по умолчанию. Если нужно включить сервис при первоначальном развёртывании, передать поле Активность=Истина в соответствующей структуре. ПолучитьНастройки и УстановитьНастройки не заменяют проверки готовности фонового пользователя, соединения и ACK.
После записи учесть до 20 секунд обновления кэша. Повторно проверить состояние и затем реальную авторизацию/доставку своим штатным заданием. Перезапуск full, новый batch_id ради проверки соединения и очистка неподтверждённого не нужны.
Полный заполненный План, файлы с ключами и значения свойств настроек в чат/журналы не отправлять. Служебный вывод примеров содержит только признаки и стадии.

Как это использовать для 500 баз
Общий модуль устанавливается в базы вместе с обновлением. Затем централизованный исполнитель развёртывания последовательно подключается к каждой базе с административными правами, проверяет её store_id и передаёт индивидуальную структуру в ПрименитьПлан. Метод доступен в серверном контексте и внешнем соединении при корректных свойствах модуля.
Индивидуальные планы поставляются защищённым каналом из реестра развёртывания. Один и тот же метод обслуживает все магазины, ручное заполнение формы в каждом магазине не требуется.
В центре сохраняются база, store_id, назначенные участники, версия настроек, результаты применения и проверки связи. Итоги нашего метода не содержат секретов; реестр секретов хранится отдельно с нужным доступом.
Настройщик вызывается при первичном развёртывании или согласованной смене параметров/ротации, не в каждом 10-секундном цикле обмена. Повторная запись тех же параметров может снова уведомить задания о перезапуске. Отслеживание версии применённой настройки выполняет исполнитель развёртывания.
Готовый диспетчер подключения к 500 базам в этом наборе не создан: для него нужны ваш механизм развёртывания, список баз/серверов и способ безопасной передачи планов. Пилот проверяет общий серверный исполнитель, который такой диспетчер будет вызывать.
Создание инфосистем и выдача ключей на стороне Шины остаются отдельной операцией. Здесь автоматизируется применение уже выданных учётных данных в 1С.
Если оба процесса используют одного участника базы, два сервиса могут получить одну пару ключей. Пока в пилоте разные участники, параметры сохраняются раздельно; объединение источников и миграция старых source_node этим модулем не выполняются.

Граница готовности
Методы и имена свойств подтверждены пользовательской справкой/скриншотами. Код новой утилиты ещё не выполнялся в платформе 1С; проверка синтаксиса, прав, сохранения полей и фактической авторизации обязательна в пилоте перед массовым запуском.
В текущем окружении ассистента нет установленной платформы 1С и доступного BSL Language Server для нового прогона; результатов прежнего анализа других модулей нельзя выдавать за проверку этой утилиты.
Очереди, версии, маршруты, source_node, batch_id и текущая full-сессия утилитой не изменяются. Поле ИмяПользователя сохраняется из прочитанных настроек без нового значения.
