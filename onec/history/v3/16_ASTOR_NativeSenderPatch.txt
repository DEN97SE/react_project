ПОЧЕМУ НУЖНА ЭТА ВЕТКА

В присланном коде для строк с непустой ВнешняяСистема вызывается:
  ПереводВJSONДляШины.ЗаписьВнешняяСистема_JSONСообщение(...).
Его реализация не предоставлена. Наш пакет уже является сериализованным JSON,
поэтому не передаём его повторному сериализатору и не предполагаем его формат.

Действующий общий отправитель пишет тело через КодировкаТекста.ANSI. Для нашего
пакета требуется UTF-8 без BOM. Эта ветка вызывает отдельный модуль, использующий
известный API СервисыИнтеграции из вашего кода, с корректным закрытием ресурсов.

Отправитель возвращает штатную структуру ЕстьОшибки / ТекстОшибки или
ЕстьОшибки / ИдентификаторСообщения. Статус сохраняет действующая приватная
процедура ЗафиксироватьИзмененияВОчередиШины. Квитанции продолжают обрабатываться
действующим ОбработатьКвитанцию по транспортному идентификатору.

Важные условия проверки:

1. ВнешняяСистема = KP_SUPPLIER не должна входить в результат
   КХ_ОбменШиныОпера.СистемыСобственнойОчереди(). Общая выборка очереди исключает
   эти системы. Для нашего нового имени обычно изменений списка не требуется,
   но фактический список нужно проверить.
2. Канал исходящей записи не должен совпадать с внутренним EDO-каналом,
   исключаемым в ОчередьДляВыгрузки(). Использовать отдельный маршрут кабинета.
3. Включен = Ложь в настройках оставляет записи в ожидании; наша ветка их
   не отправляет и не переводит в Ошибка только из-за административного выключения.
4. Получатель и канал уже сохранены в записи. При изменении текущих настроек
   непустая очередь не перенаправляется автоматически: отправитель сообщает конфликт.
   Имя сервиса и код отправителя в родной записи не хранятся и берутся из настроек.
   Менять их при наличии ожидающих сообщений можно только как явное переключение
   маршрута с отдельной проверкой; сравнить их с прежними значениями по записи нельзя.
5. ДоставкаПодтверждена в штатной очереди означает квитанцию действующего транспорта.
   Применение данных ДО/бэкендом подтверждается отдельно согласно контракту.
6. Родные задания отмены зависших/удаления старых записей распространяются и на
   KP_SUPPLIER, пока их правила явно не скорректированы. Сроки хранения и отмены
   проверить до промышленного включения; квитанция не равна применению на бэкенде.
