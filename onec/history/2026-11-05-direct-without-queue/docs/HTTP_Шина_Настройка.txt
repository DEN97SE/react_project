ТЕКУЩИЙ МАРШРУТ ПО ПРИСЛАННОЙ РАБОЧЕЙ СХЕМЕ, 05.11.2026

Ничего не записываем в прикладной регистр очереди. Новые регистры, константы, обёртки Opera/ПК и изменения штатного модуля не требуются.

1. Сохранить узлы Astor, DocumentManager и внутренний обмен FromDO → ToAstor / FromAstor → ToDO.
2. Для справочников использовать Astor_to_kp → МаршрутизаторПоСодержимому → Http_kp_Astor → From_kp_Astor → Astor.
3. Для данных ДО на сайт использовать DO_to_kp → тот же маршрутизатор → Http_kp_DO → From_kp_DO → DocumentManager.
4. configuration в параметрах сообщения: Astor / DocumentManager. Это не поле JSON. При отладке посмотреть фактическое значение перед маршрутизатором. Для неизвестного значения исходный код возвращает пустую коллекцию — не считать это доставкой.
5. HTTP-метод, URL и endpoint брать из реально рабочего узла. ТЗ предлагает PUT для справочников, но методы ПодготовкаЗапроса сами HTTP-метод не задают.
6. Сохранить Authorization = Integration.Параметры.API_key. Не менять на X-API-Key и не дописывать префикс без фактического контракта.
7. Тело — поток исходного JSON. Не делать дополнительную сериализацию строки. Для нового отправителя используется UTF-8 без BOM.
8. Обратные каналы уже есть. Проверить, какое тело/параметры поступают в сервис Астора для 200/400/401/500 и таймаута. Метод ОбновлениеМетрик лишь читает КодОтветаHttp, дальнейшей обработки в показанном коде нет.
9. Входящий сервис KP.GET отдельно передаёт тело в message_kp → kp_to_DO → DocumentManager. Он не заменяется GET-опросом бэка. Для перехода на POST нужен согласованный метод в шаблоне и изменение вызывающего клиента.
10. В KP первоначально изменить текст «Проверка в ДО!» на «Передано в Шину для доставки в ДО». Это честно описывает уровень подтверждения. Проверку JSON, media type, лимита и HTTP-статусов доработать по поддерживаемому API; в присланном коде они не реализованы полностью.

АСТОР:
- Заменить КХ_КП_ОбменАстор и КХ_КП_ТранспортШины текстами из текущей поставки.
- Сборщик данных сохраняется. Формат шести наборов проверить на реальном endpoint; для транспортной проверки можно отправить прежний рабочий JSON без изменений.
- В ПолучитьНастройки указать реальные имена метаданных сервиса и исходящего канала, коды отправителя/получателя. Имена метаданных Астора и подписи узлов Шины могут различаться.
- Включен по умолчанию Ложь. Перед включением использовать тестовое подключение и убедиться, что сообщение попадает в Astor_to_kp с configuration=Astor.
- Успешный результат ОтправитьJSON означает только ОтправленоВШину. Не показывать пользователю «сайт обновлён» до разбора ответа бэка.
- Старые задания ПодготовитьИзменения / ОтправитьСообщенияКабинета / ОчиститьОчередьКабинета для кабинета остановить. Другие задания не трогать.
- Существующие строки старого варианта не удалять автоматически. Их разбор — отдельная административная задача, новый код их не читает и не меняет.

ПРОВЕРКИ НА СТЕНДЕ:
A. Маленький рабочий JSON: параметр Astor → только Http_kp_Astor; тело запроса совпадает с исходным.
B. DocumentManager → только Http_kp_DO. Отсутствующее/неизвестное configuration не должно считаться успехом.
C. Authorization приходит в том же виде, что у рабочего вызова; секреты не включаются в диагностические выгрузки.
D. Для 200/202/204/400/401/429/500, таймаута и потери ответа установить, что реально возвращает канал и как работает политика ошибок Шины. 202 не равно применению, а 200 с бизнес-ошибкой в теле не равно сохранению.
E. Перезапуск Шины и повтор HTTP не создают неконтролируемых дублей на бэке. Если безопасный повтор не подтверждён, не включать бесконечный retry.
F. Для KP проверить отсутствующий Content-Type, повреждённый/пустой JSON, крупное тело, недоступный ДО и повтор одного КП. Ответ о передаче в Шину не подменяет подтверждение записи в ДО.
G. Отдельно проверить включённость стандартной обработки сервисов интеграции в тестовой базе: присланный штатный код может выходить для тестовой базы. Защита автоматически не обходится.

НЕ ПОДТВЕРЖДЕНО: компиляция в установленной Шине/1С, реальные URL/методы/тело бэка, параметры обратного сообщения, прикладной обработчик КП ДО, регистрация изменений в Асторе. Наличие работающего транспорта не доказывает эти части.
