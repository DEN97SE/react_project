Это подтверждено поиском по полному тексту и просмотром HTTP-клиентов/списка методов. ПолучитьТелоКакСтроку используется у синхронного HTTPОтвета и ещё при обработке изображений, а не как входящее сообщение Шины.

Нельзя подставить ОбработатьОтветAPIВ2 вместо входящего события сервиса Астора: другой тип входных данных, другой момент вызова и другие побочные действия.

Модули используют существующую ОчередьВыгрузкиДанныхShelfSpaceCenter и журнал ошибок ShelfSpace. Они не подключаются к кабинету автоматически. Ранее согласованный запрет обращений кабинета к ОчередьШины сохраняется; чужое хранилище не используется как замена.

## Где искать дальше

В Конфигураторе Астора открыть Сервисы интеграции → сервис, реально связанный с каналом ответа кабинета → модуль сервиса и назначенные обработчики событий получения сообщения. Если обработчик вызывает общий модуль, проследить вызов до него. Имя узла From_kp_Astor принадлежит Шине и может не совпадать с именем канала метаданных Астора, поэтому одного поиска этого имени недостаточно.

Также полезен глобальный поиск ОбработкаПолучения, ПолучитьТелоКакПоток, СервисыИнтеграции. Нужны код получения тела и параметров входящего сообщения и фактическая привязка обработчика к каналу. Сигнатура события не выдумывается по HTTP-клиенту ShelfSpace.

Активные модули кабинета по этим вложениям не менялись. Найденные общие приёмы проверки кода/JSON не доказывают совместимость формата ответа ShelfSpace с бэком кабинета. Подписку ShelfSpace не переносить вместе с записью в её очередь; для регистрации изменений кабинета требуется отдельное решение.

В справочных копиях для репозитория замаскированы встроенные ключи стороннего API изображений. Оригиналы вложений не изменялись. Анализ не включал выполнение кода и обращения к внешним сервисам.
