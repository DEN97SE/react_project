# Кабинет поставщика: HTTP через Шину и буфер в существующей очереди

Последнее решение пользователя от 05.11.2026: разрешено использовать ОчередьШины. Запись удаляется только после подтверждённого успеха бэка. Максимальный срок жизни недоставленного пакета — 72 часа от постановки, затем точечное удаление с записью в журнал регистрации, включая пакеты с ошибками. Это заменяет предыдущий запрет работы с регистром.

Новых регистров и констант нет. Интеграция1СШина и её переопределяемый модуль не изменяются. Публичный регистратор вызывается как есть. Техническая готовность: тексты подготовлены, сквозной приём HTTP-результата ещё не привязан и не проверен, поставка выключена по умолчанию.

## Повторное использование

- Интеграция1СШина.ЗарегистрироватьОбъектВОчереди — существующая экспортная регистрация готовой строки JSON.
- КХ_КП_ТранспортШины.ОтправитьJSON — уже подготовленная отправка UTF-8 через сервис интеграции, configuration=Astor; добавлен необязательный ID попытки.
- КХ_КП_ДанныеАстора — прежняя сборка шести наборов.
- КХ_КП_СлужебныйОбмен — прежние JSON, парсинг, SHA и проверка поля.
- КХ_ОбменШиныОпера.СистемыСобственнойОчереди — существующая точка исключения наших строк из общей обработки. Добавляется KP_SUPPLIER, остальные метки сохраняются. Собственные отправители Opera/ПК должны выбирать только свои метки, не весь расширенный перечень.

ShelfSpace-функции записи статусов/очистки не переносятся: у них другая очередь и контракт. Из модуля ЗаданиеОтправкаДанныхGMCS видны только ссылки в исходнике, полного кода нет, поэтому его совместимость не заявляется. Другие проекты/чаты пользователя автоматически недоступны; доступны подключённый DEN97SE/react_project, рабочие файлы и вложения.

## Текущие модули

- КХ_КП_ОбменАстор: настройки, полная сборка. ОтправитьПолныйСнимок теперь ставит JSON в буфер; возвращает ПоставленоВОчередь, а не успех сайта.
- КХ_КП_ТранспортШины: существующий низкоуровневый отправитель; в рабочем потоке вызывается обработчиком очереди.
- КХ_КП_ОчередьКабинета: новый адаптер регистрации, отложенной отправки, сопоставления результата и точечной очистки.
- КХ_КП_ПриемАстор: разбор внутреннего JSON-отчёта Шины, вызов адаптера очереди. Это не готовая привязка события сервиса.
- КХ_КП_ТестыОбмена: подготовленные тесты JSON, границ TTL и классификации временных HTTP-ошибок; в 1С пока не запускались.

## Что настроить

1. Сначала подключить внутренний отчёт HTTP через From_kp_Astor и событие получения сообщения сервиса Астора; проверить тестовым пакетом. Присланные обновления метрик только читают код HTTP и сами отчёт не создают.
2. Проверить реальный контракт бэка: признак применения, безопасные повторы и защита от устаревших полных снимков. Один ID в параметрах Шины не обеспечивает дедупликацию на бэке.
3. Добавить KP_SUPPLIER в фактический перечень исключений. Проверить фильтры своих обработчиков Opera/ПК. Не возвращать эту метку в штатный поток при оперативной паузе.
4. Заполнить реальные имена метаданных сервиса и исходящего канала, коды отправителя/получателя. HTTP URL и Authorization остаются в Шине.
5. Все новые общие модули серверные, неглобальные; клиентские контексты, вызов сервера и привилегированный выключены. Техническому пользователю нужны права чтения/записи/удаления регистра. Штатный регистратор временно меняет привилегированный режим; обёртка восстанавливает исходный режим даже при ошибке.
6. После проверки включить обмен. Регистрация и отправка разделены. Нужен один активный отправитель кабинета.

```bsl
Результат = КХ_КП_ОбменАстор.ОтправитьПолныйСнимок();
КХ_КП_ОчередьКабинета.ОтправитьОжидающие();
КХ_КП_ОчередьКабинета.ОчиститьИстекшие();
```

Отправку запускать, например, каждую минуту, очистку — каждые 5 минут. Физическое удаление просроченного пакета происходит при следующем запуске задания; ровно на границе 72 часов новый вызов отправки уже не начинается. Пауза Включен не останавливает приём результатов/очистку; срок жизни продолжает истекать.

## Ключи и данные

Метка владельца KP_SUPPLIER + маркер KP_HTTP_BUFFER_V1 отличают новые пакеты. Полный JSON в СтроковыйОбъект, служебные поля в существующем Объект. Начальный ключ ИдентификаторСообщения, установленный регистратором, не меняется; полученный транспортный ID хранится в маркере. Удаление/изменение выполняется менеджером записи с полным ключом всех пяти измерений.

Перед вызовом регистратора проверяется отсутствие совпадающих ID+узел под блокировкой: его штатный набор записей фильтруется шире, чем наш полный ключ. Уникальный UUID создаётся на каждый пакет. Тело и дедлайн неизменны при повторе. Старые записи KP_SUPPLIER с другими форматами автоматически не обрабатываются и не удаляются — нужна отдельная миграция, это не повод очистить весь регистр.

Дедлайн хранится в UTC. Даты регистрации/отправки в штатных полях — даты сеанса, как у существующего регистра. После успешного возврата ОтправитьJSON строка остаётся. После истечения ожидания результата (по умолчанию 900 с) повторяется тот же пакет; после временной ошибки — не ранее 60 с, с учётом Retry-After. Новый ID попытки не заменяет постоянный ID пакета.

## Результат и ограничения

Шина должна сформировать внутренний supplier.http.result с packet_id, attempt_id, http_status, applied, retry_after_seconds. applied выставляется по согласованному результату API, не по факту отправки в Шину. В текущем проекте контракта удаление по успеху требует HTTP 200 и applied=true. 202/204 автоматически успехом не считаются.

Невременные ошибки и неподтверждённое применение останавливают автоматическую отправку до истечения TTL. Нет отдельного архива недоставленного тела после удаления: пользователь выбрал жёсткие 3 суток. Журнал содержит ID и статус, не JSON и ключи. Уже начавшийся HTTP-запрос нельзя отменить удалением локальной строки, поздний ответ не воссоздаёт запись.

Сравнения с последним успешным снимком и долговечной ревизии нет: удалённая очередь не заменяет источник состояния. Подписки на изменения ещё не подключены. При разных полных снимках бэк должен обеспечивать порядок/версии; один активный отправитель сам по себе не доказывает порядок применения Шиной.

Синтаксический структурный скрипт и проверки состава файлов выполнены. Компиляция/исполнение в 1С и Шине, запросы на базе, SQL-права, обработчики входящих событий и реальные HTTP-результаты не проверены. Не включать автоматические повторы до проверки их безопасности на бэке и восстановления приёма ответов.
